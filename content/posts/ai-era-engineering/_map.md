## 각주 / 참고문헌

- **1편**(유스케이스): Naur·Brooks + 유스케이스 3표준서(Jacobson 1992·Bittner&Spence 2002·Cockburn 2001).
- **2편**(모델검증): 각주 없음 — 사용자 자체 방법론(`model-verification` 스킬: 화면/오브젝트다이어그램 검증). §5 '목록에서 선택' 역추적 휴리스틱. 억지 인용 배제.
- **3편**(디버깅): David J. Agans, 《Debugging: The 9 Indispensable Rules》(AMACOM, 2002).
- **4편**(유닛테스트): Meszaros(*xUnit Test Patterns*, 2007 — 테스트 더블 분류)·Martin(*Clean Code*, 2008 — FIRST)·Beck(*TDD: By Example*, 2002). 본문에 *명시적으로 등장하는 개념*에만 부착(억지 배제).
- **에필로그**: `[^canon]` — 여정에서 읽은 정전만(Code Complete·GoF Design Patterns·Fowler Refactoring·Agans Debugging). 개인 회고: 디버깅 고통→테스트→설계/패턴→아키텍처→유스케이스로 *거꾸로* 배운 길 = 시리즈 순서의 역방향. 착지: "다 책에 있었는데 흘려듣다가 LLM 시대에 다시 핵심 기술이 됨." LLM 파이썬 절차코드=불안한 아키텍처 비유. ai-coding 에필로그(사람의 격)와 공명.

## 논지 뼈대

- **2편** = model-verification: 유스케이스(행위 축)×도메인모델(구조 축)에 구체값 하나(정상+예외)를 흘려 **오브젝트 다이어그램(Mermaid `flowchart`)**으로 검증. 화면 투영 + 오브젝트 다이어그램 = 같은 작업(TS 실행은 사용자 요청으로 제거). 코드 이전 *설계* 검증(=첫 대화의 '연역적 검증'). 갭=모델결함(담을 값 없음)/UC결함(단계 없음). §5 **전제 역추적 → 시스템 경계(구현 범위) 누락 방지**. '목록에서 선택'·'로그인부터 시작'류 전제 = X를 낳은 **단계·절차**+조회수단(화면·API)이 경계 안에 있어야. 예: 로그인 전제 → 사용자등록·권한할당·인증·비번변경 절차가 숨음(누락 방지). **UC≠화면 엄격 구분**(등록 화면은 UC 아님; UC=목적적 절차). 'X를 낳은' 주체는 '유스케이스'보다 **'단계·절차'**(선택값마다 별도 UC 함의 회피, 사용자 교정). 초기 'UC(화면)' 혼용은 잘못된 학습자료發 오류. **되먹임→유스케이스 SSOT**. 주문 결제거절→재시도 스냅샷. ai-coding 5편(시뮬레이션)의 실행판. ⚠️ classDiagram `["라벨"]{}` 조합은 Mermaid 파싱 실패 → flowchart로.
- **3편** = 사용자 디버깅 파이프라인: 재현(데이터 확보)→환경/의존성→경계 이진탐색(위치)→가설-실험 루프(원인). 3부 "유닛은 선형, 통합은 지수(2^(m·n))·pⁿ"로 유닛테스트의 *왜*. **개인 회고 삽입**(물리 1학년 실험실 ↔ 디버깅=인과관계 증명, 사용자). 하이젠버그·불확정성·반증 = 물리 비유가 뼈대.
- **4편** = 유닛테스트 *어떻게*: 행동 vs 구현 / AAA / 경계·예외 / 테스트 더블(과용 금지) / FIRST / 테스트=명세 / 흔한 실패(동어반복·커버리지 맹신) / AI가 짤 때(반증조건 명시·사람 오라클). "통과가 아니라 깨뜨리기를 목표로."
