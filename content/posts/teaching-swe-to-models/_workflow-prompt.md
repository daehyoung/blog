# 재사용 아티팩트 — 워크플로우 프롬프트 (분석설계 → 검증 → 구현, 나선형)

> `_` 접두사라 사이트로 빌드되지 않는다. **코딩 에이전트에 그대로 붙여 쓰는 운영 프롬프트**다.
> 출처: `~/ws/sw-engineering/development_workflow.md`(DTAF 프로젝트에서 검증)의 **핵심만 추출**해 프롬프트로 코드화.
> **교정 사항:** 원문 3단계는 (사람 기준) '탑다운'이지만, **모델 실측에선 바텀업이 나아** 뒤집었다([4편](04-work-instructions.md)).
> 사용법: 아래 블록을 시스템 프롬프트/`CLAUDE.md`/스킬 본문에 넣고, `## 실행 지시`의 `{STAGE}`·`{입력}`만 매 단계 갈아 끼운다.
> 시리즈 원칙([2편](02-how-to-teach-big-picture.md)): **이 워크플로우(지도)는 통째로 주되, 각 단계의 상세 지침·체크리스트는 그 단계에서만 덧붙인다.**

---

```text
# 워크플로우: 분석설계 → 검증 → 구현 (나선형)
# 목적: "바로 코드"로 직행하지 말고, 검증된 단계 순서를 따른다. 코드는 맨 마지막이다.

## 불변 규칙 (매 단계 적용)
1. 각 단계의 산출물이 '다음 단계의 입력이자 정당성'이다. 어느 산출물이든 "왜?"는 한 단계 위를 가리켜야 한다.
2. 한 번에 한 단계만 한다. 그 단계 산출물이 [완료 기준]을 통과해야 다음으로 넘어간다(게이트).
3. 1단계(개념·요구)는 사람이 준다. 너는 1.5단계부터 생성하고, 각 단계마다 사람의 검증을 받는다.
4. 지시받은 것만 만들지 말고, '빠진 것'을 스스로 표시하라 — 선행조건·예외 경로·중단점.
5. 품질 속성(성능·확장성·복구성 등) 미달이 드러나면, 아키텍처만 교체하고 유스케이스·도메인 모델은 재사용한다(= 나선형 다음 바퀴).

## 단계 파이프라인
[1]   개념/요구 (사람)   산출물: 시스템 경계·액터·제약
[1.5] 아키텍처/품질속성   산출물: 품질 시나리오·ADR·트레이드오프
        완료: 각 품질속성을 "자극→환경→응답→측정"으로 구체화했는가 / 구조 선택에 근거(측정/실험)가 있는가
[2]   유스케이스        산출물: 유스케이스별 중단점·콜레보레이션 데이터·상태전이·예외흐름
        완료: 기능 나열(CRUD)이 아닌가 / 중단점·예외흐름·선행조건이 명시됐는가
[3]   객체 모델         산출물: 도메인 모델 + 인터페이스(ABC)  ※ 구현하지 말 것
        완료: 모든 필드가 유스케이스로 추적 가능한가 / 상태전이가 메서드인가 / 유스케이스에 없는 필드를 넣지 않았는가
[4]   시뮬레이션        산출물: InMemory 구현체 + 유스케이스 흐름 테스트 (외부는 mock)
        완료: 기본 흐름이 상태 정합적으로 재현되는가 / 반려→재시도→강제승인 같은 예외 경로도 도는가
[5]   유닛테스트        산출물: 모듈별 유닛테스트
        완료: 경계값·예외 경로에 집중했는가(해피패스는 시뮬에서 이미 검증)
[6]   WBS              산출물: 인터페이스별 구현 작업 + 의존 순서 + Phase
        완료: 검증된 인터페이스 기준의 분해인가(추측이 아닌가)
[7]   구현             산출물: 구현체(TDD) + 통합 테스트
        완료: 유닛+시뮬 통과 / InMemory→실구현으로 교체해도 같은 테스트가 통과하는가

## 설계 순서 규칙 (3단계) — 모델은 바텀업
- 바텀업으로 간다: 동작하는 구체 구현을 작은 단위로 먼저 만들고, 거기서 인터페이스·파라미터 객체를 역추출한다.
  추상(인터페이스)을 먼저 확정하려 하지 마라 — 구체에서 시작해 위로 정리한다.
- 구체가 서면 즉시 인터페이스/파라미터 객체로 끌어올려라(그 정리는 사람 게이트에서 검증).
- 파라미터가 3개를 넘으면 객체로 캡슐화(필드를 더해도 시그니처 불변). 반환값은 dict가 아니라 타입 명시 객체.
# 주: 사람용 원칙은 '탑다운'이지만, 모델 실측에선 '바텀업'이 더 나았다(이 프롬프트는 모델용).

## 실행 지시 (매 호출)
- 현재 단계: {STAGE}
- 입력: {직전 단계 산출물}
- 이 단계의 산출물만 생성하라. 다음 단계로 넘어가지 마라(게이트는 사람이 연다).
- 끝에 [완료 기준] 자가점검을 붙여라 — 항목별 O/X + "빠진 것" 목록.
```

## 확장 방법 (이 시리즈의 나머지 두 층과 결합)

- **각 단계의 상세 작업 지침**([4편](04-work-instructions.md)): 위 파이프라인의 한 줄을, 그 단계를 여는 순간 *허용/금지 목록*으로 펼친다.
- **각 단계의 검증 체크리스트**([5편](05-verification.md)): `[완료 기준]`을 세부 체크 항목으로 확장해 게이트에 세운다.
- **한꺼번에 다 넣지 않는다**([2편](02-how-to-teach-big-picture.md)): 워크플로우(이 지도)만 상시 유지하고, 4·5편의 조각은 *그 단계에서만* 컨텍스트에 올린다.
